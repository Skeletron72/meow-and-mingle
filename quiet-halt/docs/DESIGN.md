# Архитектура

## Данные мира отдельно от визуала
`WorldState` (scripts/core/world_state.gd) — единственный источник правды: сетка 80×60 клеток
(земля, высоты углов клеток), объекты (`idx → {id, rot, st}`), проекты, жители, флаги, найденные страницы.
Он не содержит узлов, сериализуется в JSON (`to_dict/from_dict`) и версионирован.
Представления (`TerrainView`, `ObjectsView`) слушают сигналы `World` и перестраивают чанки 16×16.

## Команды
Любое изменение мира проходит через `World.apply(cmd)`:
`place`, `remove`, `replace`, `set_st`, `paint_rect`, `height_rect`, `flag`. Команды — словари,
поэтому их можно проверять, логировать, откатывать и отправлять по сети. Редактор ландшафта и
перестройка зданий (фаза 7) добавятся как новые команды без правки рендера.

## Мультиплеер (задел)
- Одиночная игра = хост без клиентов; логика мира уже живёт в `World`, а не в сцене.
- `Game.profile` (инвентарь, кошелёк, внешность) отделён от `WorldState` — профиль путешествует с игроком,
  город принадлежит хосту.
- План (фаза 8): клиент шлёт «намерение» (RPC) → хост проверяет права → `World.apply` → рассылка команды;
  новичку — снапшот чанков; `MultiplayerSpawner` создаёт аватары; транспорт за интерфейсом (ENet → Steam/WebRTC).
- Погода детерминирована (`seed + дата + блок часов`) — у всех участников совпадает без синхронизации.

## Время и сезоны
`Clock` читает системное время (+ тестовое смещение). Сезон — функция месяца и полушария
(Южное = сдвиг на 6 месяцев). `EnvCtl` непрерывно интерполирует цвета неба, света, листвы и снега по «фазе года»
и подстраивает длину дня под сезон. Пропущенные дни при загрузке догоняются (`World.process_days`, не больше 30).

## Графика
Весь контент — процедурные низкополигональные меши (`MeshKit`) с цветом в вершинах; один тун-шейдер
(`toon.gdshader`) даёт изгиб мира (глобальные uniform’ы), сезонную окраску, снег на верхних гранях,
ночное свечение окон. Вода и небо — отдельные шейдеры. Все ассеты — код, поэтому проект чист по лицензиям.
