## 1. Слой платформы `Platform` (делаем первым)

Одна автозагрузка с интерфейсами; реализации выбираются по флагам сборки (`OS.has_feature("rustore")`, `"yandex_web"`, `"standalone"`).

```
Platform
 ├─ ads        show_rewarded(placement) → result, show_interstitial(), is_ready()
 ├─ iap        products(), buy(sku) → receipt, restore(), consume(sku)
 ├─ save       load_cloud()/save_cloud(dict), conflict resolution (по max прогрессу)
 ├─ analytics  event(name, params), set_user_property(), flush()
 ├─ social     leaderboard_submit(id, score), leaderboard_top(), share(text)
 ├─ push       schedule_local(id, delay_s, text), cancel(id), request_permission()
 ├─ review     request_review()
 └─ info       store_id, locale, safe_area(), age_rating
```

- Заглушки `Dummy*` для редактора и тестов (мгновенно «покупка успешна», «реклама показана»).
- Правило: игровой код **никогда** не обращается к SDK напрямую, только через `Platform`.

## 2. Android (RuStore, AppGallery, GetApps, Galaxy Store)

1. **Шаблоны экспорта** Godot 4.7 для Android, JDK и Android SDK (cmdline-tools), Gradle-сборка (нужна для плагинов).
2. **Пресеты:** `RuStore` (флаг `rustore`, пакет `ru.<студия>.warmpaw`), `Huawei`, `Xiaomi`, `Samsung`. Общий код, разные плагины и пакет не меняется.
3. **Параметры:** портрет, архитектуры arm64-v8a (+ armeabi-v7a для старых; смотреть на размер), minSdk — минимум для Godot 4.7, targetSdk — актуальный требуемый магазином, разрешения только необходимые (интернет, вибрация, уведомления), иконка (adaptive), сплэш в цвет игры.
4. **Подпись:** релизный keystore хранить вне репозитория, резервная копия в двух местах; для Play-версии отдельный upload key. Потеря ключа = невозможность обновлять приложение.
5. **Формат:** RuStore принимает APK и AAB; AppGallery — APK/AAB; для сторов с ограничением размера — AAB + удаление ненужных ABI.
6. **Плагины на Kotlin/Java** (Godot Android plugin v2): RuStore Billing/Pay, Update, Review, Push; AppMetrica; рекламные SDK (Yandex Mobile Ads, VK Ads); локальные уведомления. Для каждого — тонкая обёртка с сигналами в GDScript.
7. **Строки магазина** (название, описание, что нового) — в `store/ru/*.md`, чтобы версионировать вместе с кодом.

## 3. Яндекс Игры (HTML5)

1. Web-экспорт Godot: без потоков (`thread support` выкл.), сжатие, цель — **быстрая первая загрузка** (ленивая подгрузка не нужных на старте ресурсов).
2. Мост `JavaScriptBridge` → Yandex SDK: `ysdk.adv` (реклама), `player` (облачные данные), `payments`, `leaderboards`, `environment` (язык/ориентация), `features.LoadingAPI` (готовность).
3. Особенности: нет локальных уведомлений, свои правила размера и FPS; требования площадки по рекламе (не показывать до ГТО/интерфейса, звук гаснет на время рекламы).
4. Что подготовить: билд ≤ лимита площадки (проверить на момент подачи), иконка и обложка (разные размеры), описание, теги.
5. Тот же `Platform` с реализациями `Yandex*`; сейвы — через `player.setData/getData` с локальной копией.

## 4. Другие каналы (после RuStore)

- **VK Mini Apps / VK Play Игры** — тот же веб-билд с адаптером VK Bridge.
- **Telegram Mini App** — веб-билд, платежи через Telegram Stars (при необходимости).
- **Google Play / App Store** — бесплатная витрина для диаспоры, без монетизации в РФ.
- **PC (Steam/itch)** — после мобильного релиза, портрет → окно с рамкой.

## 5. Аналитика и мониторинг

- AppMetrica (Android SDK, плагин) + события из таблицы в 06. Для веб — Яндекс Метрика (отдельный счётчик).
- Крэши: AppMetrica Crash, источники ANR; свой логгер в `user://logs` (последние 200 KB) + кнопка «Отправить отчёт» в настройках.
- Дашборды: воронка FTUE, удержание по когортам, прохождение уровней, экономика (источники/стоки), монетизация, реклама (fill rate, eCPM).
- Удалённый конфиг (JSON, версионируемый): сложность уровней, цены, частота рекламы, активное событие. На старте — файл на хостинге с кэшем; позже — собственный бэкенд.

## 6. Сохранения и античит

- Версия сейва 5 (FTUE-шаги, валюты, задачи, события, настройки). Миграция 4 → 5 в `GameState._migrate`.
- Облако: Яндекс/VK — встроенное; RuStore — собственный бэкенд позже (до тех пор — резервный экспорт кода/файла).
- Локальный античит: подпись сейва (HMAC с ключом из сборки) и проверка монотонности времени (`last_visit_unix`, защита от сдвига часов для офлайн-дохода).
- Покупки: на старте проверка квитанции через SDK RuStore; позже серверная валидация (Yandex Cloud Function).

## 9. CI/CD и версии

1. GitHub Actions: проверка (Godot headless: `modes_test`, `smoke_test`), сборка Android (шаблоны из кэша), артефакты `*.aab/apk`, номер сборки = число коммитов.
2. Подписание — секреты репозитория или отдельный закрытый джоб.
3. Версионирование: `major.minor.build`; change log из коммитов (`docs/CHANGELOG.md`), «Что нового» из него.
4. Ветки: `main` = релиз, `develop` = ночные, `release/x.y` — заморозка перед магазином.
5. **Размер репозитория:** вынести `assets/packs` (сырые архивы) в отдельный приватный репозиторий или Git LFS; переписать историю без непроверенных паков (см. 05).
